# Поддержка Foundry VTT — техническое задание

Сайт развивается в сторону игры в **Foundry VTT** (система **dnd5e**). Принцип: сайт остаётся сайтом,
Foundry получает данные **через экспорт** (макрос, файл, позже — модуль), а сам сайт под Foundry не перекраивается.
Карты уже выгружаются сценой Foundry — см. `docs/map-editor.md`, этап 10.

### Этап 2. Персонаж: конструктор ↔ актёр
Код — `characterActor`, `characterPackage`, `presetFromActor` в `site/foundry-export.js`; в конструкторе —
`foundryCharacter()` (снимок персонажа), `openFoundry()`, `importFoundryActor()` в `site/builder.js`. Сам конструктор не менялся,
только кнопки **«В FOUNDRY»** и **«ИЗ FOUNDRY»** на панели.
- [x] Экспорт персонажа в актёра `character` dnd5e — макросом (папка «Mephistopheles Terminal / Персонажи», повторный экспорт
      обновляет того же актёра: постоянный ключ `S.fid`) или JSON для «Import Data»:
  - характеристики (итоговые, с прибавками), хиты (готовым числом — переопределение максимума), скорость;
  - предмет класса (`identifier` = id основы, `levels` = уровень → бонус мастерства, кость хитов);
  - умения расы (`feat` тип «race»), основного класса до текущего уровня (с выбранными вариантами), архетипа(ов) — тип «class»;
  - черты, снаряжение из слотов (надето), дары и Э.Г.О. (текстом), свои записи, объекты вне слотов;
  - **Свет** и **Рассудок** — ресурсы dnd5e (первый и второй);
  - биография: описание, сводка (раса, класс, уровень, СЛ, атака, Свет, Рассудок, кость хитов), выборы, замечания ДМ-у
- [x] Импорт актёра Foundry («Export Data») обратно: свой актёр несёт полный пресет во `flags.pm5e.preset` и возвращается
      целиком (имя — из Foundry); чужой — имя, уровень (сумма уровней классов), характеристики (метод «Вручную»), описание,
      архетип (подкласс/класс по названию) и черты по названиям

      спасброски — по одному из каждой группы «А, Б или В», навыки — «выберите N из …»); нарушения — в «Требует внимания ДМ-а»,
      навыки сверх класса не ошибка (черты, предыстория). В Foundry — `abilities.*.proficient` и `skills.*.value`, обратно — так же.
      Тесты — `tests/unit/proficiencies.test.mjs`

## 3. Форматы

### Пакет `pm5e-foundry` (этап 1)
```
{ format: "pm5e-foundry", version: 1, source: "<origin сайта>", exported: "<ISO>",
  items: [Item…], actors: [Actor…], journals: [JournalEntry…] }
```
- Документы — данные Foundry (`name`, `type`, `system`, вложенные `items`/`pages`), плюс служебное `_folder`
  («Бестиарий», «Архетипы/Имя») — путь папки внутри «Mephistopheles Terminal». Для «Import Data» `_folder` убирается.
- `flags.pm5e`: `key` (`<раздел>/<uid записи без раздела>`, у способностей архетипа — `#<номер>`), `cat`, `url`
  (ссылка на запись Базы знаний), `exported`; плюс подробности раздела (`level`, `gift`, `ego`, `base`, `category`).
  Область флагов `pm5e` = id будущего модуля.
- Данные dnd5e — только устойчивые поля (v3–v5): описание, требования, `type.value`, редкость, `activation`
  у действий существ, `senses` и плоско, и в `ranges` (лишнее Foundry отбрасывает).

## 5. Что берём из сеттинга Project-Moon-TTRPG
Разобрано 2026-10-12 (`src/` сеттинга). Своя механика (2d6, ST/SP, ранги, Clash) нам не нужна — у нас dnd5e.
- **Статусы как стакающиеся предметы** (`type: status`, `stacks`, `stackMax`, `priority`) + **лоток статусов** на токене
  (`apps/status-tray.js`), API макросов (`status-macro-api.js`). Компендиум `packs/status-pmttrpg-srd` — 67 статусов
  (Bind, Bleed, Burn, Charge, Fragile, Poise, Rupture, Sinking, Tremor…) с описаниями на английском.
  У нас канон статусов — `mechanics/statuses.json` (46, RU/EN); переносим механику, тексты — наши.
- **EasyEffects** (`easy-effects/`) — мини-язык триггеров («[Always Active] lose (Bind) movement; [End of Round] lose all Bind»).
  Для dnd5e нужен свой небольшой набор триггеров: начало/конец раунда или хода, при попадании — урон Горения, Кровотечения и т. п.
  Брать язык целиком дорого; сначала — фиксированные правила для каждого статуса, язык — если не хватит.
- **Иконки** `assets/icons/limbus_assets/` и `Statuses/` (webp) — для статусов и чата; часть уже есть на сайте (`Assets/Icons/`).
- Оформление листа и чата (стили `src/styles`) — по мотивам, для своих вкладок «Свет» и «Э.Г.О.».
