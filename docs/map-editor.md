# Редактор карт Города — техническое задание

Отдельная страница сайта (`maps.html`, код — `map-app/`) для рисования карт по вселенной Project Moon.
Карты **не играются** на сайте: их экспортируют в Roll20, Foundry, Owlbear и т. п.
Ориентир по духу и удобству — **Dungeondraft**.

## 1. Решения, принятые с заказчиком

| Вопрос | Решение |
|---|---|
| Типы карт | тактические боевые, локации/районы, планы зданий и подземелий |
| Сценарий | рисуем здесь → скачиваем → переносим в VTT (Roll20 и др.) |
| Экспорт | PNG / JPG / WebP (выбор пикселей на клетку, с сеткой или без) и **Universal VTT `.dd2vtt`** (стены, двери, свет) |
| Сетка | квадратная, шестиугольная, без сетки |
| Графика | загружаемые фоны, тайлы и объекты, ручное рисование, генерация |
| Ассеты | рисует команда (дизайнер и художник), пока — **временные заглушки**; пользователи подключают свои папки **локально, без загрузки на сервер** |
| Формат картинок | PNG, база **256 px на клетку**; допускаются картинки от 16×16 до 1024×1024 и SVG |
| Где лежат канонические ассеты | `Assets/Maps/` на сайте (кэшируются для работы без сети) |
| Масштабируемый контент | `Assets/Maps/scalable/` — вывески, логотипы, их подтипы; **всё, что лежит в папках, само появляется в выборе разновидности** |
| Хранение проектов | файл на диске (`.pmmap`), автосохранение в браузере (IndexedDB). Аккаунт — см. §8 «Открытые вопросы» |
| Обмен наборами | только канонический набор на сайте; пользовательские наборы — личные (локальные) |
| Этажи | да, этажи с лестницами + отдельный вариант карты «с крышами» |
| Устройства | ПК + планшет (мышь, сенсор, стилус) |
| Доступ | только вошедшие пользователи (сервер не нагружается — всё локально) |
| Язык | русский и английский интерфейс |
| Связь с сайтом | Лор и Районы (палитры, контекст генерации), Ширма (узел ссылается на карту) |
| Первый этап | ручной редактор + экспорт |

### Этап 2. Художественные инструменты
- [x] Кисти местности (грязь, кровь, вода, мусор, трещины, мазут, песок, мох) с мягким краем, ластик (Alt);
      рисуются поверх полов, под стенами. Текстура «земли» под всем этажом
- [x] Пути и кривые (дорога, разметка, тропа, труба, провод, забор, рельсы, отбойник, столбы) — заготовки + свой стиль:
      ширина, текстура, пунктир, обводка, сглаживание. Картинка вдоль пути — **лентой** (изгибается по кривой без
      разрывов, углы ломаной скругляются; заборы, рельсы) или **отдельно** с шагом (столбы, фонари); масштаб картинки.
      Сегменты для ленты рисуются бесшовными по длине: картинка повторяется вдоль пути, «вверх» картинки — поперёк
      **Составные пути:** две параллельные линии по бокам (рельсы, двойная труба, бордюры) + объекты поперёк через шаг
      (шпалы) + широкая линия с текстурой (насыпь). Заготовка «Рельсы» собрана так; старая «Рельсы (лентой)» оставлена
- [x] Свет: источники (радиус, цвет, яркость), тени от стен и закрытых дверей (окна пропускают свет),
      общая темнота карты; запекание в картинку (по выбору) + `lights` в `.dd2vtt`; мягкие тени под стенами
- [x] Подписи и номера комнат (нумерация подряд), подложка, «только для мастера»; слои «только для мастера»;
      экспорт в версии для игроков и мастерской
- [x] Крыши (щелчок по комнате или прямоугольник, скаты у прямоугольных) и экспорт «с крышами»; в редакторе — скрыты / полупрозрачны / видны
- [~] Лестницы — пока объекты в `objects/stairs/` (лестница, винтовая, стремянка, люк); связи между этажами нет
- [x] Фон-картинка этажа с подгонкой под сетку (пикселей на клетку, сдвиг, прозрачность, «подогнать размер карты»)
- [ ] PDF для печати (по желанию) — отложено

### Доработки
- [x] **Объёмные стены (псевдо-3D, как в Enter the Gungeon):** сама стена — тонкая тёмная линия, текстура ложится
      гранью высотой «Высота грани» клеток. Направление грани задаётся отдельно для стороны внутри помещения и снаружи:
      вниз ↓ (грань видна у стен, обращённых к зрителю), вверх ↑, по периметру, нет. За стеной другая комната — грань
      рисует она как внутреннюю (без двойных граней). В дверях граней нет, окна грань не прерывают. Грани лежат под
      объектами; мебель «у стены» и «в углу» встаёт к основанию грани. Высота 0 — прежняя плоская стена
      (так открываются старые карты). Код — `wallFaces` в `geom/walls.ts`, отрисовка — `drawFaces` в `render/render.ts`
- [x] **Стыки и наложение граней:** грань «внутри» видна только внутри своей комнаты, «снаружи» — только вне её
      (на углах, в т. ч. у треугольных помещений, они не залезают друг на друга); ближние к зрителю грани поверх дальних.
      «По периметру» выбирается отдельно внутри и снаружи, на углах грани сходятся по биссектрисе (без перекосов и
      пропусков). У отдельной стены «внутри» — сторона слева по ходу рисования, «снаружи» — справа
- [x] **Верхняя линия стены не прерывается** над дверями, окнами и арками (режет её только «Убрать стену»);
      **толщина 0** — стена без линии (для света и VTT остаётся)
- [x] **Отдельная стена комнаты:** щелчок по линии стены (инструмент выделения) выбирает только её — свои текстура,
      толщина, дальность и грани (`Room.edgeStyles`), «Как у всей комнаты» — сбросить, Del — убрать стену.
      Настройки переезжают вместе с комнатой и сохраняются при слиянии, если ребро осталось
- [x] **Проёмы в объёмных стенах:** дверь и окно вырезают стену вместе с гранью, а их картинка вписывается в грань
      по её форме (перекос диагональных стен, сжатие по дальности). Форма — в свойствах проёма: перемычка сверху и
      подоконник снизу (доли высоты грани; по умолчанию у двери 0.15 / 0, у окна 0.3 / 0.3), арка, ширина.
      ∅ «Пустой проём» (без картинки) — арка или вырез: взгляд и свет проходят, в `.dd2vtt` нет портала.
      На плоской стене и на стене без грани (вертикальная при «вниз ↓») проём рисуется как раньше, сверху
- [x] **Дальность грани:** высота грани в клетках (по умолчанию 0.5); текстура стены не обрезается, а сжимается —
      вся высота картинки ложится на грань, по длине стены плитка = footprint клеток
- [x] **Убрать стену** (инструмент ✂, X): щелчок — ребро комнаты или отдельной стены от угла до угла, протяжка — участок
      (гараж, навес). Это проём без стены (`kind: "gap"`): нет ни линии, ни грани, свет и взгляд проходят, в `.dd2vtt`
      нет ни стены, ни портала. Двери и окна на убранном участке удаляются. Щелчок по убранной стене (в редакторе —
      красный пунктир) возвращает её

### Этап 3. Формат наборов и редактор правил
- [x] Визуальный редактор `_meta.json` — библиотека → «✎ Разметить»: дерево папок, файлы (несколько сразу — Ctrl/Shift),
      название RU/EN, вид, слой, ppc, масштабируемость, пиксель-арт, теги, размер в клетках, группа вариантов, правила,
      комплекты папки. Пустое поле = наследуется (подсказка «↑ …»), «Итог» показывает, что получится. Локальный набор
      сохраняется в браузер и **прямо в папку на диске** (Chrome/Edge, если папку подключали выбором папки), канон — до
      перезагрузки + «Скачать _meta.json» (ZIP по папкам → `Assets/Maps/`, затем `npm run gen:maps`)
- [x] Правила размещения (§5): объект с правилом сам прилипает к стене / в угол / в центр комнаты / к дороге и
      поворачивается лицом к комнате (Alt — без правил, галочка в панели инструмента). Нарушения отношений
      («рядом с», «не ближе», двери, максимум на комнату, тип комнаты, внутри/снаружи) подсвечиваются на карте и в
      свойствах объекта; кнопка «⚠ N» внизу выделяет нарушителей. Тип комнаты задаётся в свойствах комнаты.
      Вес, минимум, районы и состояние пока только хранятся — их использует генерация (этап 4)
- [x] Комплекты: `sets` в `_meta.json` папки, в библиотеке — плитки 🧩; ставятся целиком (поворот, отражение, правило
      позиции комплекта). Новый комплект — выделить объекты на карте → «Сохранить как комплект».
      Варианты одного объекта — `group` у файлов: в библиотеке одна плитка «×N», ставится случайный вариант;
      вариации по правилам — случайные поворот, отражение, масштаб, оттенок (оттенок можно задать и вручную)

### Этап 4. Генерация

      двери так, чтобы все комнаты были связаны, вход снаружи, окна по наружным стенам, мебель по правилам набора
- [x] Здания и подземелья по параметрам: тип здания (офис, склад, лаборатория, жилой дом, бар, клиника, мастерская,
      логово, магазин), размер, число комнат, стиль, крыша; подземелье — комнаты по всей карте, коридоры, вход-лестница
- [x] Улицы Задворок: кварталы делятся улицами (главные — с разметкой) и переулками, на участках — дома с комнатами,
      дверью на улицу и крышей; площади (мощение, скамейки, фонари); вдоль дорог — фонари со светом, урны, машины
- [x] Расстановка содержимого: мебель и комплекты по правилам (§5), укрытия (теги `cover`), ловушки (тег `trap`,
      отдельный слой «Ловушки» только для мастера), следы состояния (грязь, трещины, мусор), свет, номера комнат
- [x] «Раскраска стиля» — галочка во вкладке «Оформить набросок»: полы и стены по стилю (Крыло, Задворки,
      Лаборатория, Руины) и типу комнаты; тип без подсказки угадывается по размеру и форме
- [x] Зерно (seed): поле и 🎲 в окне; после генерации внизу карты — «🎲 Другой вариант» (заменяет результат),
      «⚙ Параметры», «✓ Оставить». Генерация — одно действие истории (Ctrl+Z)

- [x] **Стена растёт от периметра пола:** у объёмной стены «вниз ↓» / «вверх ↑» основание грани — на линии стены (край пола

## 4. Наборы ассетов

### Папки
```
Assets/Maps/
├── manifest.json        генерируется: node scripts/gen-map-assets.mjs (руками не править)
├── floors/              материалы пола (kind: floor) — бесшовные текстуры
├── walls/               текстуры стен (kind: wall)
├── portals/doors/       двери (kind: door);  portals/windows/ — окна (kind: window)
├── terrain/             текстуры кистей местности (kind: terrain) — бесшовные, непрозрачные: форму задаёт кисть
├── roofs/               кровля (kind: roof)
├── objects/<категория>/ мебель, контейнеры, улица, офис, мастерская…
├── corps/<x>-corp/      наборы Крыльев: walls, floors, doors, windows, roofs, signs, objects (правило «Район Крыла»)
└── scalable/            масштабируемый контент: вывески, логотипы, плакаты…
    └── signs/associations/<ассоциация>/<вариант>.svg
```
Любая вложенность папок допустима: **папки = категории и подтипы, файлы = разновидности**.
В редакторе у выбранного объекта есть цепочка списков «категория → подтип → вариант», собранная
из соседних папок и файлов. Новый файл или папка в `Assets/Maps/` появятся в редакторе после
`node scripts/gen-map-assets.mjs` (на Vercel скрипт запускается при сборке).

### Картинки
- PNG/WebP/JPG — **256 px на клетку** по умолчанию (`ppc` в `_meta.json` меняет это). Картинка 512×256 = объект 2×1 клетки.
- Картинки меньше 256 px по большей стороне (16×16 … 255) считаются объектом в 1 клетку (масштабируются).
  Для пиксель-арта — `"pixelated": true` (без сглаживания).
- SVG — размер берётся из `width/height` или `viewBox` по тем же правилам; рисуется чётко на любом масштабе.
- Размер в клетках можно задать явно: `"footprint": [2, 1]`.

### `_meta.json` (необязательный, в любой папке; наследуется вниз по дереву)
```json
{
  "name": { "ru": "Вывески", "en": "Signs" },
  "kind": "object",
  "scalable": true,
  "ppc": 256,
  "layer": "above",
  "tags": ["street"],
  "files": {
    "hana.svg": { "name": { "ru": "Ханa", "en": "Hana" }, "footprint": [2, 1], "group": "hana" }
  },
  "rules": { "place": "wall" },
  "sets": {}
}
```
- `kind`: `object` (по умолчанию) | `floor` | `wall` | `door` | `window` | `terrain` (кисти) | `roof` (кровля).
- `scalable: true` — объект свободно масштабируется (вывески, логотипы), а не привязан к клеткам.
- `layer`: `below` (по умолчанию) или `above` — над стенами.
- `group` (только у файла) — группа вариантов одного объекта в папке (ящик, ящик-доски, ящик-окованный).
- `rules` — правила размещения (§5). Сливаются **по полям**: правило папки + поля файла поверх.
- `sets` — комплекты этой папки (§5). Всё это удобнее править в «✎ Разметить», а не руками.
- Для редактора разметки `manifest.json` хранит и исходные `_meta.json` (`metas`), и собранные комплекты (`sets`).

### Локальные наборы
Пользователь подключает папку с диска (Chrome/Edge — выбор папки, остальные — выбор нескольких файлов
с сохранением путей). Те же правила папок и `_meta.json`. Файлы хранятся в IndexedDB браузера,
на сервер ничего не уходит. Карта с локальными ассетами при сохранении в `.pmmap` кладёт их внутрь файла.

## 5. Правила размещения (этап 3)
Код: разбор и умолчания — `normRules` в `map-app/src/assets/tree.js`, геометрия и проверки — `map-app/src/geom/place.ts`
(ими же будет пользоваться генерация этапа 4). **Соглашение художникам: верх картинки — задняя сторона объекта**
(спинка стула, задняя стенка шкафа, изголовье кровати). «Лицом к комнате» = верх картинки к стене.

```json
"rules": {
  "place": "wall",            // free | wall | corner | center | road — куда прилипает при установке
  "face": true,               // автоповорот (по умолчанию да для wall/corner/road)
  "gap": 0,                   // отступ от стены / края дороги, клетки
  "where": "inside",          // any | inside (в комнате) | outside
  "clearDoors": true,         // не загораживать двери (по клетке прохода с каждой стороны)
  "near":  [{ "to": "#table", "dist": 0.5 }],   // рядом с … (зазор не больше dist клеток)
  "avoid": [{ "to": "#flammable", "dist": 2 }], // не ближе dist клеток к …
  "rooms": ["office", "lab"], // типы комнат (пусто — любые); список — ROOM_TYPES в geom/place.ts
  "districts": ["backstreets"], "state": ["new", "worn", "ruined"],  // контекст генерации
  "weight": 1, "min": 0, "max": 4,              // частота и количество на комнату (max 0 — без ограничения)
  "rotate": "90",             // none | 90 | any — случайный поворот
  "flip": true,               // случайное отражение
  "scale": [0.9, 1.1],        // случайный масштаб
  "tint": ["#e0d4c0"]         // случайный оттенок из списка (умножение цвета)
}
```
- Цель в `near` / `avoid`: `#тег`, `@группа`, имя файла в той же папке (`table.svg`), путь от папки (`../office/plant.svg`)
  или от корня набора (`/objects/containers`) — файл или вся папка.
- **Позиции:** `wall` — спиной к ближайшей стене (комнаты или отдельной), вдоль стены шаг полклетки; `corner` — в выпуклый
  угол комнаты, вплотную к обеим стенам; `center` — в центр масс комнаты; `road` — вдоль ближайшего пути, у края,
  спиной от дороги (скамейка смотрит на дорогу). Если рядом нет стены/угла/пути — ставится как обычно.
- Проверяются при установке (красная рамка и подсказка) и на карте: `where`, `rooms` (если у комнаты задан тип),
  `near`, `avoid`, `clearDoors`, `max`. `weight`, `min`, `districts`, `state` — для генерации.

**Комплекты** (`sets` в `_meta.json` папки):
```json
"sets": {
  "dining-4": {
    "name": { "ru": "Стол и 4 стула", "en": "Table with 4 chairs" },
    "rules": { "place": "wall" },
    "items": [
      { "file": "table.svg", "x": 0, "y": 0 },
      { "file": "chair.svg", "x": -0.5, "y": -1 },
      { "file": "chair.svg", "x": 0.5, "y": 1, "rot": 180, "flip": false, "scale": 1 }
    ]
  }
}
```
Координаты — центры предметов в клетках (относительно любой точки: комплект ставится по центру своей рамки), пути
`file` — как у целей правил. Из правил у комплекта работает `place` — комплект прилипает целиком.

## 5а. Генерация (этап 4)
Код — `map-app/src/gen/`: `rng.ts` (зерно), `kit.ts` (каталог, стили, профили комнат и зданий), `layout.ts` (общие и
наружные стены, двери, входы, окна), `furnish.ts` (расстановка), `generate.ts` (четыре генератора). Генераторы не
зависят от браузера и проверяются тестами на настоящем каноне (`tests/unit/maps-gen.test.mjs`).
- **Зерно.** Всё случайное — только `makeRnd(seed)`; одно зерно + те же параметры и наборы = та же карта.
- **Что попадает в генерацию:** объекты с правилами (§5) из выбранных наборов («Наборы для мебели»), комплекты с правилами
  (правила папки наследуются комплектом), `#debris` — следы состояния, `#cover` — укрытия, `#trap` — ловушки.
  Подходит ли объект: `where`, `rooms` (тип комнаты), `state` (состояние), `districts` (поле «Район / фракция»),
  `max`/`min` на комнату; частота — `weight` × «любимые» теги типа комнаты (`ROOM_PROFILE` в `kit.ts`).
- **Как ставится объект:** точка-подсказка по `place` (у случайной стены, в углу, в центре, рядом с целью `near`) →
  то же размещение, что и вручную (§5) → проверки: целиком в комнате, не в стене, не на проходе у двери,
  не пересекается с другой мебелью, правила не нарушены. Не вышло за 12 попыток — берётся другой объект.
- **Двери:** все комнаты связаны (остовное дерево, коридоры — первыми) + немного лишних дверей; у залов (склад, мастерская,
  бар, магазин) вход шире (рольставня, двустворчатая), если стена позволяет.
- **Стили** (`STYLES`): полы по типу комнаты, стены, двери, окна, кровля, земля, состояние и цвет света.
  Новый стиль, тип здания или профиль комнаты — одна запись в `kit.ts`.

## 6. Форматы файлов

### Карта `.pmmap`
ZIP: `map.json` (документ) + `assets/…` (локальные ассеты, использованные на карте).
Канонические ассеты хранятся ссылкой `canon:<путь>`. Документ — см. `map-app/src/model/types.ts`.
У комнаты необязательный `edgeStyles`: `[{ a, b, style }]` — свои настройки отдельных стен (ребро a–b, отличия от `wall`).
Стена (`WallStyle`): `asset`, `color`, `width`, и для объёмной — `height` (клетки), `inner` / `outer`
(`down` | `up` | `normal` | `none`). Проём (`Portal.kind`): `door` | `window` | `gap` (проём без стены);
у двери и окна необязательные `top`, `bottom` (доли высоты грани) и `arch`; `asset: null` — пустой проём.

В `map.json` (этап 5) необязательные `district` (Район: id, имя, цвет, Крыло, все имена) и `links` (ссылки карты:
`{ title, url }`), у подписи — `link`.

### Экспорт `.dd2vtt` (Universal VTT, format 0.3)
- `resolution.pixels_per_grid` — выбранный размер клетки, `map_size` — в клетках.
- `line_of_sight` — стены комнат и отдельные стены, разрезанные в местах проёмов.
- `portals` — двери (`closed: true`). Окна — настройка экспорта: пропускают взгляд (разрыв в стене) / как стена / как дверь.
- `lights` — источники света этажа (`range` в клетках, цвет ARGB). `environment.baked_lighting` — запечён ли свет в картинку,
  `ambient_light` — общий свет (без освещения карты — `ffffffff`). Если VTT сам считает свет, запекание лучше выключить.
- `image` — PNG в base64.
- Шестиугольная сетка в `.dd2vtt` не описывается — VTT нужно переключить на гексы вручную.

### Картинка
Размер клетки: 50 / 70 (Roll20) / 100 / 140 / 200 / 256 px. Сетку можно включить в картинку.
Ограничение браузера ~16384 px по стороне — редактор предупреждает и предлагает меньший размер клетки.

## 8. Открытые вопросы и ограничения

  На этапе 1 синхронизации через аккаунт нет (только файл и браузер). Нужно решить: делать ли её вообще.
- Список обязательного содержимого канонического набора и тематических заготовок генерации — `docs/map-sprites.md` (ведёт художник).
- **Под вопросом (2026-10-10, «можно, но не уверен в нужности»):** тайные двери, экспорт фрагмента карты, настройка окон
  в `.dd2vtt` у каждого окна, лестницы со связью этажей, ключ карты (описания к номерам комнат). Не делать без запроса.
- Список типов комнат (`ROOM_TYPES`), стилей и профилей зданий (`gen/kit.ts`) — черновой; уточнить с командой.
- Нужны ли правила «в стене» (декор, который ставится на стену поверх, как картины и вывески) — сейчас это `wall` с `gap`.

### Известные ограничения этапа 1 (кандидаты на доработку)
- Стены разной толщины на общем ребре двух комнат рисуются обе (видна более толстая).
- Окна в `.dd2vtt` выбираются одной настройкой на весь экспорт.
- Синхронизации через аккаунт нет (см. выше).
- Правила проверяют описанные прямоугольники объектов, а не их форму (круглый стол «занимает» квадрат).
- `corner` работает только с углами комнат (у отдельных стен углов не ищет); `road` — по оси пути и его ширине.
- Разметка канона в браузере живёт до перезагрузки: канон меняется только через репозиторий (`Assets/Maps/` + `npm run gen:maps`).
- Запись `_meta.json` прямо в папку — только Chrome/Edge и только для наборов, подключённых выбором папки
  (подключённые раньше этапа 3 — переподключить); в остальных случаях — «Скачать _meta.json».
- Кисть пересчитывает местность этажа целиком после каждого мазка; на очень больших картах с тысячами мазков это может подтормаживать.
- Свет и тени запекаются в картинку; динамики (двери открываются) в самом редакторе нет — это делает VTT по `.dd2vtt`.
- Лестницы не связывают этажи (нет перехода «вверх/вниз»), это просто объекты.
- Генерация (этап 4): здания прямоугольные (комнаты — деление прямоугольника или коридор посередине); подземелье — по всей
  карте; улицы — на всю карту, без изгибов. Площадь мостится мазками кисти. Типы комнат без своей мебели в каноне
  (санузел, кухня, бар…) пока обставляются общей мебелью — ждём ассеты команды.
- Окна и двери генератор ставит только на стены комнат (не на отдельные стены).
- Объёмные стены: грань «по периметру» на углах может слегка перекрываться. Грань — проекция, свет и тени
  считаются по линии стены (основанию стены); у «вниз»/«вверх» видимый верх стены поднят над ней. Картинки дверей и окон в каноне пока нарисованы видом сверху — в грани они
  растягиваются; для объёмных стен художнику нужен вид спереди (вся картинка = высота проёма).
- Этап 5: ссылка на карту работает только в браузере, где карта есть (карты не уходят на сервер); на другом устройстве —
  сначала открыть файл `.pmmap` (id карты сохраняется в файле, после этого ссылка заработает). Районы читаются из
  статического `Assets/<язык>/world/world.json`, правки карты Города в Firestore редактор увидит после `canon-pull`.
  Ширма не умеет ссылаться на конкретный узел, поэтому из карты можно сослаться только на Базу знаний и страницы сайта.
