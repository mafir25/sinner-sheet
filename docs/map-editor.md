# Редактор карт Города — техническое задание

Отдельная страница сайта (`maps.html`, код — `map-app/`) для рисования карт по вселенной Project Moon.
Карты **не играются** на сайте: их экспортируют в Roll20, Foundry, Owlbear и т. п.
Ориентир по духу и удобству — **Dungeondraft**.

## 1. Решения, принятые с заказчиком

| Вопрос | Решение |
|---|---|
| Типы карт | тактические боевые, локации/районы, планы зданий и подземелий |
| Сценарий | рисуем здесь → скачиваем → переносим в VTT (Roll20 и др.) |
| Экспорт | PNG / JPG / WebP (выбор пикселей на клетку, с сеткой или без) и **Universal VTT `.dd2vtt`** (стены, двери, свет) |
| Сетка | квадратная, шестиугольная, без сетки |
| Графика | загружаемые фоны, тайлы и объекты, ручное рисование, генерация |
| Ассеты | рисует команда (дизайнер и художник), пока — **временные заглушки**; пользователи подключают свои папки **локально, без загрузки на сервер** |
| Формат картинок | PNG, база **256 px на клетку**; допускаются картинки от 16×16 до 1024×1024 и SVG |
| Где лежат канонические ассеты | `Assets/Maps/` на сайте (кэшируются для работы без сети) |
| Масштабируемый контент | `Assets/Maps/scalable/` — вывески, логотипы, их подтипы; **всё, что лежит в папках, само появляется в выборе разновидности** |
| Хранение проектов | файл на диске (`.pmmap`), автосохранение в браузере (IndexedDB). Аккаунт — см. §8 «Открытые вопросы» |
| Обмен наборами | только канонический набор на сайте; пользовательские наборы — личные (локальные) |
| Этажи | да, этажи с лестницами + отдельный вариант карты «с крышами» |
| Устройства | ПК + планшет (мышь, сенсор, стилус) |
| Доступ | только вошедшие пользователи (сервер не нагружается — всё локально) |
| Язык | русский и английский интерфейс |
| Связь с сайтом | Лор и Районы (палитры, контекст генерации), Ширма (узел ссылается на карту) |
| Первый этап | ручной редактор + экспорт |

## 2. Порядок этапов (дорожная карта)

Статус: `[x]` — сделано, `[~]` — частично, `[ ]` — не начато.

- [x] Этажи (добавить, переименовать, порядок, нижний этаж виден полупрозрачно)
- [x] Слои объектов (видимость, блокировка, порядок, «над стенами»)
- [x] Комнаты: прямоугольник и многоугольник, слияние и вырезание (Alt), материал пола, стиль стен
- [x] Отдельные стены (ломаные линии)
- [x] Двери и окна — ставятся на стену, делают в ней проём

- [x] Временные заглушки ассетов (SVG)

### Этап 2. Художественные инструменты
- [x] Кисти местности (грязь, кровь, вода, мусор, трещины, мазут, песок, мох) с мягким краем, ластик (Alt);
      рисуются поверх полов, под стенами. Текстура «земли» под всем этажом
- [x] Пути и кривые (дорога, разметка, тропа, труба, провод, забор, рельсы, отбойник, столбы) — заготовки + свой стиль:
      ширина, текстура, пунктир, обводка, сглаживание. Картинка вдоль пути — **лентой** (изгибается по кривой без

      Сегменты для ленты рисуются бесшовными по длине: картинка повторяется вдоль пути, «вверх» картинки — поперёк
- [x] Свет: источники (радиус, цвет, яркость), тени от стен и закрытых дверей (окна пропускают свет),

- [x] Крыши (щелчок по комнате или прямоугольник, скаты у прямоугольных) и экспорт «с крышами»; в редакторе — скрыты / полупрозрачны / видны
- [~] Лестницы — пока объекты в `objects/stairs/` (лестница, винтовая, стремянка, люк); связи между этажами нет
- [x] Фон-картинка этажа с подгонкой под сетку (пикселей на клетку, сдвиг, прозрачность, «подогнать размер карты»)

## 3. Устройство (этап 1)

```
map-app/
├── maps.html               точка входа (собирается в dist/maps.html)
└── src/
    ├── main.tsx, App.tsx   вход, экран выбора карты, рабочее место
    ├── i18n.ts             строки интерфейса RU/EN (корень помечен .notranslate)
    ├── model/              формат карты (types, создание, проверка/миграция)
    ├── geom/               сетки и привязка, многоугольники (polygon-clipping), стены и проёмы
    ├── state/              хранилище документа, отмена/повтор
    ├── assets/             дерево наборов (tree.js — общий с генератором), канон, локальные папки
    ├── storage/            IndexedDB (карты, наборы), файл .pmmap (JSZip)
    ├── render/             отрисовка на Canvas 2D (экран и экспорт одним кодом)
    ├── tools/              инструменты (выделение, комната, стена, проём, объект)
    ├── export/             PNG/JPG/WebP, .dd2vtt
    └── ui/                 панели, диалоги
```

- Единица координат — **клетка** (1 = одна клетка = 5 футов). Пиксели появляются только при отрисовке.
- Отрисовка — Canvas 2D (а не WebGL, как планировалось изначально): проще экспорт в любое разрешение,
  SVG-заглушки рисуются чётко на любом масштабе. Если на больших картах станет тесно — перенос на PixiJS
  (код отрисовки изолирован в `render/`).
- Сборка: `npm run build` → `vite build` (Ширма) + `vite build --config vite.maps.config.mjs` (редактор) + `copy-static`.

## 4. Наборы ассетов

### Папки
```
Assets/Maps/
├── manifest.json        генерируется: node scripts/gen-map-assets.mjs (руками не править)
├── floors/              материалы пола (kind: floor) — бесшовные текстуры
├── walls/               текстуры стен (kind: wall)
├── portals/doors/       двери (kind: door);  portals/windows/ — окна (kind: window)
├── terrain/             текстуры кистей местности (kind: terrain) — бесшовные, непрозрачные: форму задаёт кисть
├── roofs/               кровля (kind: roof)
├── objects/<категория>/ мебель, контейнеры, улица, офис, мастерская…
└── scalable/            масштабируемый контент: вывески, логотипы, плакаты…
    └── signs/associations/<ассоциация>/<вариант>.svg
```
Любая вложенность папок допустима: **папки = категории и подтипы, файлы = разновидности**.
В редакторе у выбранного объекта есть цепочка списков «категория → подтип → вариант», собранная
из соседних папок и файлов. Новый файл или папка в `Assets/Maps/` появятся в редакторе после
`node scripts/gen-map-assets.mjs` (на Vercel скрипт запускается при сборке).

### Картинки
- PNG/WebP/JPG — **256 px на клетку** по умолчанию (`ppc` в `_meta.json` меняет это). Картинка 512×256 = объект 2×1 клетки.
- Картинки меньше 256 px по большей стороне (16×16 … 255) считаются объектом в 1 клетку (масштабируются).
  Для пиксель-арта — `"pixelated": true` (без сглаживания).
- SVG — размер берётся из `width/height` или `viewBox` по тем же правилам; рисуется чётко на любом масштабе.
- Размер в клетках можно задать явно: `"footprint": [2, 1]`.

### `_meta.json` (необязательный, в любой папке; наследуется вниз по дереву)
```json
{
  "name": { "ru": "Вывески", "en": "Signs" },
  "kind": "object",
  "scalable": true,
  "ppc": 256,
  "layer": "above",
  "tags": ["street"],
  "files": {
    "hana.svg": { "name": { "ru": "Ханa", "en": "Hana" }, "footprint": [2, 1] }
  },
  "rules": {}
}
```
- `kind`: `object` (по умолчанию) | `floor` | `wall` | `door` | `window` | `terrain` (кисти) | `roof` (кровля).
- `scalable: true` — объект свободно масштабируется (вывески, логотипы), а не привязан к клеткам.
- `layer`: `below` (по умолчанию) или `above` — над стенами.
- `rules` — зарезервировано под правила размещения этапа 3.

### Локальные наборы
Пользователь подключает папку с диска (Chrome/Edge — выбор папки, остальные — выбор нескольких файлов
с сохранением путей). Те же правила папок и `_meta.json`. Файлы хранятся в IndexedDB браузера,
на сервер ничего не уходит. Карта с локальными ассетами при сохранении в `.pmmap` кладёт их внутрь файла.

## 5. Правила размещения (этап 3, формат зарезервирован)
- **Позиция:** у стены / в стене (окно, дверь) / в углу / в центре комнаты / снаружи / внутри / у дороги; автоповорот лицом к комнате.
- **Отношения:** рядом с X (стул у стола), не ближе N клеток к Y, не загораживать двери и проходы, комплекты.
- **Контекст:** тип комнаты (склад, офис, лаборатория), Район / фракция, состояние (новое, разрушенное).
- **Вариативность:** вес/частота, минимум/максимум на комнату, случайный поворот, отражение, масштаб, оттенок, варианты.

## 6. Форматы файлов

### Карта `.pmmap`
ZIP: `map.json` (документ) + `assets/…` (локальные ассеты, использованные на карте).
Канонические ассеты хранятся ссылкой `canon:<путь>`. Документ — см. `map-app/src/model/types.ts`.

### Экспорт `.dd2vtt` (Universal VTT, format 0.3)
- `resolution.pixels_per_grid` — выбранный размер клетки, `map_size` — в клетках.
- `line_of_sight` — стены комнат и отдельные стены, разрезанные в местах проёмов.
- `portals` — двери (`closed: true`). Окна — настройка экспорта: пропускают взгляд (разрыв в стене) / как стена / как дверь.
- `lights` — источники света этажа (`range` в клетках, цвет ARGB). `environment.baked_lighting` — запечён ли свет в картинку,
  `ambient_light` — общий свет (без освещения карты — `ffffffff`). Если VTT сам считает свет, запекание лучше выключить.
- `image` — PNG в base64.
- Шестиугольная сетка в `.dd2vtt` не описывается — VTT нужно переключить на гексы вручную.

### Картинка
Размер клетки: 50 / 70 (Roll20) / 100 / 140 / 200 / 256 px. Сетку можно включить в картинку.
Ограничение браузера ~16384 px по стороне — редактор предупреждает и предлагает меньший размер клетки.

## 8. Открытые вопросы и ограничения
- **Хранение в аккаунте.** Сначала выбрано «в аккаунте (без картинок)», потом — «не загружать в Firestore новые вещи».
  На этапе 1 синхронизации через аккаунт нет (только файл и браузер). Нужно решить: делать ли её вообще.
- Список обязательного содержимого канонического набора (вывески Ассоциаций и Крыльев, мастерские, Задворки…) — ждём от команды.

### Известные ограничения этапа 1 (кандидаты на доработку)
- Проём нельзя тащить вдоль стены — его удаляют и ставят заново (при переносе комнаты двери едут вместе с ней).
- Стены разной толщины на общем ребре двух комнат рисуются обе (видна более толстая).
- Окна в `.dd2vtt` выбираются одной настройкой на весь экспорт.
- Синхронизации через аккаунт нет (см. выше).
- Объекты пока не умеют «прилипать» к стенам — это правила этапа 3.
- Кисть пересчитывает местность этажа целиком после каждого мазка; на очень больших картах с тысячами мазков это может подтормаживать.
- Свет и тени запекаются в картинку; динамики (двери открываются) в самом редакторе нет — это делает VTT по `.dd2vtt`.
- Лестницы не связывают этажи (нет перехода «вверх/вниз»), это просто объекты.
